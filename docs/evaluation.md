# 评测协议与结果

截至 2026-10-16。评测脚本与逐项结果保存在 `scripts/`、`artifacts/` 和 `evidence/`。这些结果是本地 Docker Desktop 与公开历史数据上的证据，不代表真实路侧设备的长期可用性。

## 预测

数据：UCI I‑94 西向 ATR 301 逐小时流量。原始 48,204 行按相同时间戳中位数聚合成 40,575 个不同小时；不填补训练中的缺失小时。原始文本把时间描述为本地 CST，测试统一按固定 UTC−06:00 处理；这可能与夏令时实际时钟不同。模型特征只使用已观测的过去 168 小时流量和目标小时的日历特征，不使用未来天气。

训练/验证按目标时间分界：2017 年以前训练，2017 年验证，2018 年测试。完整连续历史不足的起点被排除。单步结果来自 `scripts/train_forecast.py` 的 2018 年 4,939 个点；8 小时结果采用 2018 年 199 个相隔一天的完整起点、1,592 个目标点。误差单位是车辆/小时，WAPE 是绝对误差总和除以实际值总和。

| 2018 测试 | MAE | RMSE | WAPE |
| --- | ---: | ---: | ---: |
| 单步本地模型 | 152.036 | 239.763 | 4.585% |
| 单步前一天同小时 | 560.299 | 1025.834 | 16.896% |
| 单步上周同小时 | 343.861 | 666.580 | 10.369% |
| 8 小时直接模型，已部署 | 189.506 | 302.834 | 10.512% |
| 8 小时递推模型 | 194.052 | 305.335 | 10.764% |
| 8 小时前一天同小时 | 340.005 | 520.428 | 18.860% |
| 8 小时上周同小时 | 267.304 | 480.813 | 14.828% |

8 小时直接模型相对较强的“上周同小时”基线降低 MAE 约 29.1%。直接模型是在查看递推模型的 2018 年结果之后决定评估并采用的，因此这个 2018 年比较已用于模型选择，**不是全新盲测**。

Timer‑3.5 已用真实密钥完成连通性探测：336 点上下文预测 8 点，返回 `model=Timer-3.5`、无降级，一次调用约 1.1–1.5 s（`evidence/timer_probe.json`）。另做了 3 个 8 小时片段、24 个目标点的现场抽查（`evidence/timer_quality_spotcheck.json`）：Timer 平均 MAE 181.0、平均 WAPE 8.2%，部署的本地直接模型平均 MAE 118.4、平均 WAPE 5.4%，本地模型在 3 个片段上均略优。抽查只覆盖单站点 24 点，**不构成 Timer 质量基准**；配额、成本、长期可用性未评估。容器 scikit-learn 已固定为训练版本 1.9.0，8 点示例预测与训练环境逐位一致。

## 在线异常报警

数据：NAB `realTraffic` 的 7 个序列，合计 14 个标签窗。按时间顺序逐点回放，当前观测只与过去值比较；检测器先用前 32 点预热。当前规则采用稳健同日相位中位数/MAD、阈值 6、每资产 3 小时冷却，并要求偏差回落到 3 以下才重新布防（回差/滞环，防止持续偏差期间反复报警）。对照是过去最多 288 点的稳健中位数规则，采用相同抑制规则。使用上游 MIT 许可的 `Sweeper` 标准配置（TP=1，FP=0.11，FN=1，15% 预热不计分），在这 7 个文件内部把空检测器归一为 0、理想检测器归一为 100。

| NAB 交通子集指标 | 当前规则 | 对照规则 |
| --- | ---: | ---: |
| 子集归一标准分 | 81.079 | 80.028 |
| 标签窗检出 | 14/14 | 14/14 |
| 窗外告警 | 43 | 53 |
| 事件精确率 | 24.6% | 20.9% |
| 事件 F1 | 0.394 | 0.346 |
| 窗外告警/流数据天数 | 0.221 | 0.272 |

对照数字 **不是 NAB 58 文件官方排行榜总分**。阈值、冷却、回差和更早的局部稳健过滤等试验都看过这 7 个文件的标签，最终方案从中选择，故这里只能作为开发集结果。规则选择扫描了 12 组冷却/回差组合：冷却 2–3 小时、回差 2–4 的区间稳定在 80.7–81.1，冷却 ≥4 小时会把 9 月 16 日相邻 2 小时的两个标签窗合并处理而丢一个窗（74.2），更早的局部过滤实验 F1 略高（0.414）但标准分降到 70.869，均已回退。另按 NAB 官方“优化阈值→计分→归一”流程，用同一 7 文件子集评测了上游 numentaTM 官方结果（固定提交 `ea702d75`，`artifacts/anomaly_external_baseline.json`）：官方基线得 79.022（原始分 8.126，阈值 0.663），当前固定工况规则得 81.079（原始分 8.702）；如果去掉冷却与回差、只对原始分数流取优化阈值，当前检测器只有 58.864，说明抑制层承担了主要贡献。两者阈值都在同一批窗口上调过，仍然只是开发集比较。要证明“优秀”报警质量，需要额外、未见过的站点和已审定事件标签；当前 24.6% 精确率不满足这一目标。报警也没有经人工调查验证为真实事故/设备故障。

## 功能与容量

`scripts/smoke_test.py` 从容器外执行，覆盖认证拒绝、演示预测、报告保存与重读、知识图谱来源、回填幂等/冲突、实时报警、冷却抑制、回差未恢复抑制、回差恢复后再次报警和确认。最终镜像下 30 次顺序资产列表查询 p50 8.14 ms、p95 9.31 ms。`scripts/test_timer_contract.py` 在运行容器中以模拟响应验证安装版 SDK 0.2.6。

`scripts/load_test.py` 对 10 个独立资产各按时序送入 100 点，共 1,000 个请求。加入 PostgreSQL 连接池后，在最终镜像上顺序做了两次独立运行：两次均 1,000/1,000 返回 HTTP 200，吞吐分别 141.81、162.97 请求/秒，p95 分别 135.46、88.97 ms。原始结果见 `evidence/ingest_load_pool_run1.json` 和 `evidence/ingest_load.json`。同一台机器上跨全部轮次的吞吐在 111–187 请求/秒之间波动，受 Docker Desktop 宿主机负载影响。连接池前相同负载的 p95 为 162.58–211.41 ms；第一轮与功能验收同时运行的结果也留存，但不用于比较。报警状态写入已改为条件更新（仅在布防状态变化时写库），避免每个正常点的额外行更新。压测验证单宿主短时吞吐，不验证高可用或大规模长时间稳定性。

目前没有 Timer 的大规模质量基准、OpenRouter 报告调用、图纸 OCR/CAD 解析、跨宿主故障恢复、生产网络负载或供应商 SLA 证据。质量结论应逐项看待，不能以预测结果替代报警质量。
